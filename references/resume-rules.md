# 简历规则（大二版）

> 版式、字段结构、视觉版/ATS 版双输出，见 `resume-design.md`。
> 这里只讲内容怎么写。

## 总原则

- **一页纸**。大二不要写两页。
- **只写能兑现的**。面试官会追问每一行，写不出来的不要写。
- **动作开头，结果收尾**。不要写「负责了…」，写「做了 X，结果 Y」。
- **没有数字就写产出**：交付了什么、被谁用了、做了多少份/多少篇/多少人。

## 结构

1. 教育背景（学校 · 专业 · 年级 · 预计毕业年份）
2. 求职意向（一句话）
3. 经历与项目（2–4 条，倒序）
4. 技能（只写能当场演示的）
5. 可选：证书 / 语言 / 作品链接

## 大二素材从哪来

| 素材 | 怎么写成一条 |
|---|---|
| 课程项目 | 课程名 + 做了什么 + 用了什么方法/工具 + 交付物 |
| 社团/学生会 | 活动规模 + 你负责的环节 + 结果（到场人数、推文阅读、预算） |
| 比赛 | 赛题 + 你的角色 + 方案 + 名次/入围 |
| 兼职/家教 | 服务对象 + 你解决的问题 + 可量化结果 |
| 自媒体 | 平台 + 内容方向 + 粉丝/播放/互动 + 更新频率 |
| 帮老师/朋友做事 | 任务 + 工具 + 交付 + 被采用情况 |

## 动词表

负责 → 改成：搭建 / 整理 / 分析 / 撰写 / 协调 / 设计 / 跑通 / 复盘 / 优化

## 不要写

- 「熟悉 Office 办公软件」「吃苦耐劳」「学习能力强」——没有信息量。
- 「精通 Python」除非能现场写。
- 与岗位无关的证书堆砌。
- 空泛的自我评价段落。

## 按岗位定制时

1. 从 JD 里抽 5–8 个关键词（工具、动作、业务对象）。
2. 素材库里能对上的往前排，对不上的不要硬塞。
3. 同一段经历可以换 2–3 种写法，选最贴 JD 的那版。
4. 改完对照 JD 读一遍：HR 扫 10 秒，能不能看到「这个人干过类似的事」。

## 输出

- 只改 `output/resume_data_<jobid>.json`。
- 渲染：
  - `compass resume --job <id> --style visual` → 给 HR / 打印
  - `compass resume --job <id> --style ats` → 网申 / 投递系统
- 渲染后自己读一遍 HTML，检查：有没有空 bullet、有没有错别字、有没有编造、有没有第二页。
